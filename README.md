# 전장그룹 업무관리

여러 명이 동시에 쓰는 업무전달 리스트입니다. 서버 PC 없이 공유폴더만으로 동작합니다.
기존 '업무전달리스트' 엑셀의 파일 잠금 문제를 해결하려고 만들었습니다.

- 각자 PC에서 프로그램을 실행하면 브라우저 화면이 열림
- 누가 수정해도 다른 사람 화면에 **5초 안에 자동 반영**
- 내가 수정 중이어도 다른 사람의 저장을 **막지 않음**
- 모든 수정 이력이 남음 (누가 / 언제 / 무엇을 / 이전값 → 새값)
- 기존 엑셀 양식 그대로 내보내기

---

## 1. 동작 원리 (왜 파일 잠금이 안 생기나)

```
\\공유폴더\전장업무관리\events\
   ├─ 이가람C_1a2b3c4d.jsonl   ← 이가람C PC의 프로그램만 씀
   ├─ 이재욱M_5e6f7a8b.jsonl   ← 이재욱M PC의 프로그램만 씀
   └─ ...
```

- 각 PC의 프로그램은 **자기 파일에만** 한 줄씩 추가합니다. 파일 하나를 여러 명이 고치지 않으므로 잠금 충돌이 생기지 않습니다.
  (CAN에서 메시지 ID 하나를 ECU 하나만 송신하는 것과 같은 원리)
- 화면을 그릴 때는 모든 파일을 모아 시간순으로 합칩니다.
- 화면 주소는 `http://127.0.0.1:8765` 입니다. **내 PC 안에서만** 접속되므로 방화벽이나 포트를 열 필요가 없습니다.
- 두 사람이 **같은 업무의 같은 칸**을 동시에 고치면 먼저 저장한 값이 유지되고, 나중에 저장한 사람에게 경고가 뜹니다.
  다른 칸끼리는 둘 다 반영됩니다.

## 2. 처음 설치 (관리자 1회)

### 2-1. 공유폴더 사전 검증 (권장)
1. `share_test.bat`를 **PC 2대**에서 각각 더블클릭합니다.
2. 테스트할 공유폴더 경로를 입력합니다.
3. 두 PC 모두에서 상대 PC가 쓴 줄이 `한글테스트★▶`까지 정상으로 보이면 통과입니다.
   - 글자가 깨지거나 읽기 오류가 나면 DRM 같은 보안 프로그램이 막고 있는 것입니다. 사용 전에 IT팀 확인이 필요합니다.

### 2-2. 프로그램 받기
1. GitHub 저장소 → **Actions** → `Windows exe 빌드` → 최신 실행 항목 → 아래쪽 **Artifacts**에서 `jeonjang_tasks-windows`를 내려받습니다.
2. 압축을 풀어 둡니다. (exe는 C 드라이브에서 실행 가능, 데이터는 U 드라이브에 저장됨)

### 2-3. 설정
- 배포 파일에 `config.ini`가 이미 들어 있습니다. 기본값은 `U:\전장업무관리\data` (클라우디움 서버)입니다.
- 경로가 다르면 `config.ini`를 메모장으로 열어 `data_dir`, `backup_dir`만 고칩니다.
  - **모든 팀원이 같은 `data_dir`를 써야 합니다.**
  - 회사 PC는 C 드라이브·바탕화면 저장이 막혀 있습니다. 프로그램은 **data_dir(U 드라이브)에만** 저장합니다.

### 2-4. 기존 업무 47건 이관
1. `데이터이관.bat`를 더블클릭합니다. (1회만)
2. "47건 이관 완료"가 뜨면 끝입니다. 다시 실행하면 중복 방지를 위해 중단됩니다.
3. 초기 사용자도 함께 등록됩니다: 나대경M(관리자), 이가람C, 이재욱M, 박삼용C, 전장(공통 업무용, 로그인 불가)

## 3. 팀원 PC 설치

1. 배포 파일 압축을 풀어 둡니다. (exe는 C 드라이브에서 실행 가능)
2. `jeonjang_tasks.exe`를 더블클릭하면 브라우저가 열립니다.
3. 처음 한 번 내 이름을 선택합니다.
4. 바탕화면 바로가기: exe에서 마우스 오른쪽 버튼 → 보내기 → 바탕화면에 바로 가기 만들기

> 이 PC에서 고른 이름은 `data_dir\local\PC이름_윈도우계정_포트.json`에 저장됩니다. PC마다 따로 생기므로 복사·관리할 필요가 없습니다.

### 한 PC에서 '동시 사용' 시험하기
1. `jeonjang_tasks.exe` 실행 → 이름 A 선택
2. `2번째창_테스트.bat` 실행 → 이름 B 선택 (포트 8766, 다른 사용자로 취급됨)
3. 두 브라우저 창을 나란히 놓고 한쪽에서 수정 → 다른 쪽이 5초 안에 바뀌는지 확인

### Windows 시작 시 자동 실행 (선택)
1. `Win + R` → `shell:startup` 입력 → 열린 폴더에 exe 바로가기를 넣습니다.
2. 이미 실행 중일 때 다시 실행하면 브라우저만 열립니다. (PC당 1개만 실행됨)

## 4. 백업과 복구

- **자동 백업**: 프로그램이 켜져 있으면 하루 1번 `backup_dir\날짜\` 폴더에 events 폴더를 복사합니다. 그날 처음 켜진 PC가 수행합니다.
- **복구 순서**
  1. **모든 PC의 프로그램을 종료합니다.** (검은 창을 닫음)
  2. `data_dir\events` 폴더 이름을 `events_손상_날짜`로 바꿔 보관합니다.
  3. `backup_dir\원하는날짜\` 폴더를 `data_dir\events`로 복사합니다.
  4. 프로그램을 다시 실행합니다.
- 기록은 지우지 않고 계속 추가만 하는 방식이라, 실수로 수정한 값도 **변경 이력**에서 이전 값을 확인해 되돌릴 수 있습니다.

## 5. 사용자 추가 / 퇴사자 처리

- 관리자 화면 → **사용자 추가**에 이름을 입력합니다 (예: `홍길동M`).
- 퇴사자나 이동자는 삭제하지 않고 **'사용' 체크를 해제**합니다. 과거 업무의 담당 기록은 그대로 남습니다.

## 6. 권한

| 동작 | 누가 |
|---|---|
| 업무 등록 | 누구나 |
| 수정 · 진행내용 추가 · 완료 처리 | 주담당 · 협업자 · 관리자 |
| '전장' 공통 업무 지정 | 관리자 |
| 삭제 (숨김 처리, 이력 보존) | 관리자 |

> **보안 수준 안내**: 비밀번호 없이 이름 선택 방식입니다. 데이터가 공유폴더의 텍스트 파일이라, 비밀번호를 걸어도 폴더 접근 권한이 있으면 파일을 직접 열 수 있습니다. 즉 비밀번호는 실질적인 보안이 되지 못합니다. 권한 구분은 **실수 방지용**이고, 실제 보안은 공유폴더의 접근 권한(IT 관리)에 의존합니다.

## 7. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| "공유폴더에 접근할 수 없습니다" | 네트워크 연결, `config.ini`의 `data_dir` 경로, 폴더 쓰기 권한 |
| "저장 실패" 빨간 메시지 | 저장 시점에 공유폴더 연결이 끊긴 것입니다. 입력값은 저장되지 않았으니 연결 후 다시 저장 |
| 다른 사람 수정이 안 보임 | 5초 기다리기. 그래도 안 보이면 상대 PC의 `data_dir`가 같은지 확인 |
| 수정 순서가 이상함 | PC 시계 차이 확인 (순서는 각 PC의 시계 기준) |
| 입력 점검에 "읽지 못한 줄" 표시 | 누군가 events 파일을 직접 편집한 경우입니다. 해당 줄만 무시되고 나머지는 정상 |

## 8. 개발자용

```bash
pip install -r requirements.txt
python -m pytest -q                                   # 테스트
python scripts/import_seed.py seed_tasks.json 데이터폴더  # 이관
python run.py                                          # 실행 (config.ini 필요)
```

| 파일 | 역할 |
|---|---|
| `app/store.py` | 이벤트 로그 읽기/쓰기, 상태 재구성 (핵심) |
| `app/rules.py` | 상태 판정(지연/임박/완료), 입력 점검, 권한 |
| `app/export.py` | 엑셀 내보내기 |
| `app/main.py` | 화면 라우트, 실행 진입점 |
| `app/templates/`, `app/static/` | 화면 (외부 CDN 없음) |
| `tools/*.bat` | 공유폴더 검증, 데이터 이관 |
