# 차량 전장 회로 검증·편집 프로그램 요구사항

> 이 문서는 Claude Code로 개발할 프로그램의 요구사항이다.
> 최종 목표는 E3.series 같은 데이터 중심 하네스 설계 프로그램이며, 기능은 단계적으로 늘린다.
> 1차 마감: 2026-10-14

---

## 1. 목적

1. 기존 회로도(DWG)를 가져와 회로 데이터로 변환한다.
2. 퓨즈에서 출발해 연결된 모든 핀을 추적하고 퓨즈·전선·단자 선정 적합성을 판정한다.
3. 판정 결과를 CSV로 출력한다.
4. 회로 데이터를 수정하고 다시 DWG로 내보낸다.

## 2. 해결하려는 문제

- 현재 회로도는 선·사각형·글자로 된 그림이라 연결 정보가 없다. 검증은 사람이 도면을 보며 엑셀에 옮겨 적어 수행한다.
- 퓨즈 하나에 분기점을 거쳐 여러 유닛이 묶이고, 퓨즈와 유닛이 서로 다른 시트(파일)에 있어 수작업 추적이 어렵다.
- 분기 후 가는 지선, 커넥터 단자 한계, 시트 간 표기 불일치는 사람이 놓치기 쉽다.

---

## 3. 핵심 설계 원칙 (반드시 지킬 것)

### 3.1 데이터가 원본, 도면은 결과물
- 프로그램 내부의 **회로 데이터 모델**이 유일한 원본(Single Source of Truth)이다.
- DWG/DXF는 가져오기(입력)와 내보내기(출력) 형식일 뿐이다.
- 검증, CSV 출력, 도면 출력, 향후 Wire List·BOM은 모두 데이터 모델에서 생성한다.

```
[DWG] → 변환 → [DXF] → 가져오기(Importer) → [회로 데이터 모델] → 검증 → [CSV]
                                                    ↕ 편집
                                              내보내기(Exporter) → [DXF] → 변환 → [DWG]
```

### 3.2 모듈 분리
| 모듈 | 역할 | 의존 |
|---|---|---|
| model | 회로 요소·연결·시트 데이터 구조 | 없음 |
| importer | DXF → model | model |
| exporter | model → DXF | model |
| verifier | 추적·판정 | model, parts_db |
| parts_db | 부품 사양 마스터 조회 | 없음 |
| report | CSV 출력 | verifier 결과 |
| converter | DWG ↔ DXF 변환 래퍼 | 외부 도구 |

verifier는 DXF를 직접 읽지 않는다. 입력 형식이 바뀌어도 검증 로직은 그대로 유지되어야 한다.

### 3.3 도형 정보 보존
- 가져온 요소의 좌표·레이어·원래 도형 정보를 모델에 보존한다.
- 내보내기 시 원래 배치가 유지되어야 한다 (가져오기 → 내보내기 왕복 시 도면이 깨지지 않을 것).

### 3.4 모르는 값은 모른다고 표시
- 사양 DB에 없는 품번, 해석 불가 텍스트, 짝 없는 참조는 조용히 넘기지 않고 오류·판정 불가로 출력한다.
- 수치를 추정해서 채우지 않는다.

## 4. 회로 데이터 모델

### 4.1 요소와 속성

| 요소 | 속성 | 비고 |
|---|---|---|
| Sheet | DRAWING_NO, VEHICLE, SHEET_NO, SHEET_TOTAL, NAME, REV | 파일명에서 파싱 |
| Bus | BUS_ID, PWR_TYPE (B+/IG/ACC) | 퓨즈가 전원 종류를 상속 |
| Fuse | JBOX_NO, FUSE_NO, FUNCTION, RATING | 추적 출발점 |
| BoxTerminal | BOX, TERMINAL_NO (E74, G42 등), TERMINAL_PN | 박스 출력 단자, 단자 판정 대상 |
| WireSegment | WIRE_NO, MATERIAL, SQ, COLOR, 양 끝 접속점 | 분기 시 접미사 (55 → 55B, 55D) |
| Splice | SPLICE_NO | 통과, 모든 갈래로 분기 |
| InlineConnector | CONN_NAME (DASH↔DASH SUB 등), PIN_NO, TERMINAL_PN | 같은 핀 번호 반대편으로 통과 |
| Pin | DEVICE, CONN, PIN_NO, PIN_FUNC, LOAD_CURRENT, TERMINAL_PN | 유닛 핀, 종점 |
| SheetRef | LINK_ID, 대상 시트번호, 대상 장치/커넥터/핀, 방향 | 시트 간 연결 |
| Relay (2차) | RELAY_NO, 통과 핀 쌍 (30↔87), 코일 전류 | 접점 통과, 코일 종점 |

### 4.2 입력 규칙
- PIN_FUNC 허용 값: `B+`, `IG`, `ACC`, `GND`, `SIG` (목록 외 값은 오류)
- LOAD_CURRENT는 전원 핀에만 입력. 병렬 전원 핀은 총합을 한 핀에만 입력 (이중 계산 방지)
- 사양값(정격, 허용전류)은 회로 데이터에 넣지 않고 품번만 저장한다

### 4.3 시트 식별
- 파일명 규칙: `69001-KV405_001004_(CE_BOX)_R0.dwg`
  - 69001 = 도면번호, KV405 = 차종, 001 = 장번호, 004 = 전체 장수, CE_BOX = 시트명, R0 = 리비전
  - 장번호가 없는 형식도 있음: `69002-KV405_(AUX_FUSE_BOX)_R0.dwg`
- 같은 도면번호는 최신 리비전만 사용
- 폴더의 회로도 리스트 엑셀(`00.KMPV_JEEP_회로도리스트_*.xlsx`)과 대조해 누락 시트를 보고
- 참조 박스의 시트번호(예: `07`)는 도면번호 690**07**과 대응하는 것으로 보임 → 확인 필요

### 4.4 시트 간 연결
- 한 차종 회로가 약 35개 시트로 나뉨
- SheetRef는 양쪽에 같은 LINK_ID를 가진 짝으로 연결
- 짝 없음, LINK_ID 중복, 양쪽 정보 불일치는 오류

## 5. 가져오기 (Importer)

### 5.1 변환
- DWG는 직접 읽지 않고 DXF로 변환 후 처리 (후보: ODA File Converter, 라이선스 확인 필요)
- 폴더 단위 일괄 변환 지원

### 5.2 두 가지 가져오기 방식

**A. 블록 기반 가져오기 (1차 필수)**
- 속성 블록(퓨즈, 핀, 전선 라벨, 분기점, 참조 박스)으로 작성된 도면을 읽는다
- 연결은 선 끝점과 블록 접속점의 좌표 일치(허용오차 적용)로 판단
- 작도 규칙:
  - 선은 끝점끼리만 연결 (중간 통과는 연결 아님)
  - 3갈래 이상은 반드시 Splice 블록
  - 전선은 지정 레이어(WIRE)에만
  - 전선 라벨은 해당 선 바로 위에 배치

**B. 텍스트 기반 가져오기 (2차, 기존 도면 대량 전환용)**
- 블록화되지 않은 기존 도면의 텍스트를 패턴으로 해석한다
- 해석 대상 예:
  - 전선: `55 (1.0 LB)`, `808 (2.5 W)` → WIRE_NO, SQ, COLOR
  - 퓨즈: `IMMO F11 10A` → FUNCTION, FUSE_NO, RATING
  - 참조 박스: `BCM G-22P W(G13,START,RLY30)  07` → 장치, 커넥터, 핀/기능, 대상 시트
- 참조 박스 괄호 안 표기 순서가 박스마다 다름 (`(B+,16-6)`, `(80-10)`, `(RLY,85,G49)`) → 해석 결과는 확정이 아닌 **후보**로 만들고, 사람이 검토·수정하는 단계를 둔다
- 해석 실패 항목 목록을 반드시 출력

## 6. 추적 규칙

퓨즈에서 출발해 아래 규칙으로 따라간다.

| 만나는 요소 | 동작 |
|---|---|
| BoxTerminal, Splice, InlineConnector, SheetRef | 통과 |
| 스위치 (2차) | 통과 (닫힌 상태 가정) |
| 릴레이 접점 (2차) | 통과 |
| 유닛 전원 핀, 릴레이 코일 (2차), ECU 전원 입력 | 종점 → LOAD_CURRENT 합산 |

- ECU를 종점으로 볼지는 확정 필요 (현재 가정: 종점)
- 동시 동작은 기본적으로 전부 동시 동작(최악 조건)으로 계산

## 7. 부품 DB (별도 마스터 파일)

| DB | 열 |
|---|---|
| 전선 허용전류 | MATERIAL, SQ, 적용 환경 (실내/엔진룸), 허용전류, 출처 |
| 단자 | TERMINAL_PN, 정격전류, 수용 SQ 최소, 수용 SQ 최대, 출처 |
| 퓨즈 | 표준 용량 목록, 적용 여유율, 출처 |

- 형식: CSV 또는 엑셀 (사용자가 직접 관리)
- 수치는 사내 기준·데이터시트로 채운다
- DB에 없는 품번 → "판정 불가"

---

## 8. 판정 로직

| 판정 | 조건 |
|---|---|
| 퓨즈 | 퓨즈 용량 ≥ 하류 부하 합계 × 여유율 |
| 전선 | 퓨즈 하류 **모든 전선 구간** 허용전류 ≥ 퓨즈 용량 |
| 단자 | 경로상 모든 단자 정격 ≥ 퓨즈 용량, 해당 SQ 수용 가능 |
| 전원 종류 | 핀 PIN_FUNC = 퓨즈 PWR_TYPE |
| 연결 오류 | 퓨즈까지 추적 안 되는 전원 핀, 전류 미입력 전원 핀, 참조 짝 오류 |

판정값은 `OK` / `NG` / `판정 불가` 세 가지로 고정한다.

## 9. 출력

### 9.1 CSV 3개

**① fuse_summary.csv** (퓨즈당 1행)
시트, J/BOX, 퓨즈번호, 기능, 전원, 용량(A), 연결 핀 목록, 부하 합계(A), 경로 최소 SQ, 퓨즈 판정

**② wire_detail.csv** (전선 구간당 1행)
시트, 퓨즈번호, 퓨즈 용량(A), 회로번호, 재질, SQ, 허용전류(A), COLOR, From, To, 하류 핀, 하류 부하(A), 전선 판정, 단자 판정

**③ error_report.csv**
유형, 시트, 위치(장치/핀/회로번호), 내용

**CSV 형식 규칙**
- 인코딩: UTF-8 BOM (엑셀 한글 깨짐 방지)
- 숫자는 단위 없이 숫자로 (단위는 열 제목에 표기)

### 9.2 DWG 내보내기
- 모델 → DXF 생성 → DWG 변환
- 1차: 가져온 도면의 속성값 수정 사항을 반영해 내보내기 (원래 배치 유지)
- 2차 이후: 모델에서 도면 새로 생성

## 10. 편집

| 단계 | 편집 방식 |
|---|---|
| 1차 | 표 형식 편집 (요소 목록에서 속성값 수정) → DXF/DWG 반영 |
| 2차 | 시트 간 탐색 (참조 박스 클릭 → 대상 시트 이동), 연결 하이라이트 |
| 3차 | 그래픽 회로 편집기 (요소 배치·결선) |

## 11. 단계별 범위 (로드맵)

**1차 (2026-10-14 목표)**
- DWG↔DXF 변환 래퍼
- 블록 기반 가져오기 (방식 A)
- 데이터 모델, 다중 시트 연결
- 추적: 퓨즈 → 박스 단자 → 전선 → 분기점 → 인라인 커넥터 → 핀
- 판정 5종, CSV 3개 출력
- 속성 수정 후 DXF/DWG 내보내기
- 테스트 범위: CE_BOX (F35·F42 포함 장) + DR_UNIT 시트 2장

**2차**
- 텍스트 기반 가져오기 (방식 B) + 검토 화면
- 릴레이·스위치 통과, GND 회로, 버스 입력선 판정
- 시트 간 탐색, 연결 하이라이트

**3차**
- 그래픽 회로 편집기
- Wire List, 커넥터 핀맵, BOM 출력

**4차 이후 (E3 수준 목표)**
- CATIA EHI 전선 길이 연동 → 전압강하 판정
- 하네스 단위 관리, 포메이션 보드 도면
- 돌입전류 검토 플래그, 퓨즈 분리 제안

## 12. 테스트 케이스

```
F42 (B+, 10A) → 75 (FLRY 0.75) → DRL UNIT 1번 핀 (B+)
F35 (IG, 10A) → 90 (FLRY 0.75) → 분기점
                 → 90A (FLRY 0.5) → DRL UNIT 2번 핀 (IG)
                 → 90B (FLRY 0.5) → FOG LAMP 3번 핀 (IG)
```
기대 결과:
- F35 부하 = 두 핀 전류 합
- 90, 90A, 90B 구간이 각각 별도 행으로 판정됨
- FOG 3번 핀을 B+로 바꾸면 전원 종류 불일치 오류
- DB에 없는 단자 품번 → 판정 불가
- 참조 박스 한쪽 삭제 → 짝 오류

※ 테스트용 전류·허용전류 값은 가상값이며 실제 판정 기준이 아님
